CogniOS

Linux workload detection · Runs in userspace · Work in progress

CogniOS reads data from psutil and /proc, turns each sample into 18 features, and asks an XGBoost model whether a process is compute-bound, memory-bound, I/O-bound, or idle. In my tests, inference stays under 2 ms. I also added an Isolation Forest for unusual behavior, a rolling crash log, and a simulator for comparing scheduler ideas.

RUNS AS: USERSPACE PROCESS
PREDICTION: <2MS (XGBOOST)
ANOMALY CHECK: ISOLATION FOREST
CRASH LOG: WAL RING-BUFFER

—Writing

These are rough notes from projects I’m still working on. I’ll publish the full versions as I finish them.

I wanted CogniOS to recognize workloads without a kernel module. So I trained an XGBoost model on CPU, page-fault, and I/O data, then wrote a small /proc collector that works without root. The current model uses 18 features and usually returns a prediction in under 2 ms.

// /proc/[pid]/stat feature extraction window
psutil_snapshot() -> parse_proc_stat() -> 18-dim vector
XGBoost.predict(tensor) -> {COMPUTE: 0.88, MEM: 0.08, IO: 0.04} [1.4ms]

The model was the easy part. Running it as a background process meant dealing with startup time, model versions, changing telemetry, and crash recovery. This note walks through the data generator, feature scaling, MLflow runs, model files, and the WAL-backed ring buffer.

// Atomic telemetry buffer commit
RingBuffer::commit(record) {
  wal_log.append(record);
  if (unlikely(crash_flag)) wal_flush_dump();
}
